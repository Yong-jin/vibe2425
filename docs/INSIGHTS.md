# F2 인사이트 지표 기준과 검산

## 포함·제외 기준

| 항목 | 결정 |
| --- | --- |
| 조회 범위 | 종료일을 포함한 최근 7/14/30일을 날짜별 `GET /api/boxoffice?date=YYYY-MM-DD&type=daily`로 조회한다. 주간·주말 결과는 섞지 않는다. |
| 영화 식별 | `movieCd`로 묶는다. 같은 이름의 다른 영화는 합치지 않는다. |
| 합산 값 | 검증된 `salesAmt`, `audiCnt`만 정수로 합산한다. `salesAcc`, `audiAcc`는 날짜별로 더하지 않는다. |
| 순위 밖 영화 | 해당 날짜에 관측되지 않은 영화의 매출·관객수를 0으로 채우지 않는다. 모든 수치는 일별 Top 10 목록에서 관측된 범위다. |
| 빈 날짜·실패 날짜 | 차트에서 값을 비우고 선을 끊는다. 각 날짜의 정상·빈 날짜·실패·조회 중 상태를 별도로 센다. 오래된 캐시(`partial`)와 필수 숫자 오류는 실패로 분류한다. |
| 기간 합계·Top 순위 | 조회 기간의 모든 날짜가 정상일 때만 표시한다. 하나라도 빈 날짜·실패·조회 중이면 `—`와 부분 집계 안내를 표시한다. |
| 관객당 매출 | 모든 날짜가 정상이고 관측 관객 합계가 0명보다 클 때만 관측 매출 합계 ÷ 관측 관객 합계를 계산한다. 그렇지 않으면 `—`다. |
| 표시 단위 | 원·명 단위의 `BigInt` 합산을 모두 마친 뒤 억 원·천 명으로 변환한다. 차트 좌표만 축소한 안전한 수로 변환한다. |

## 화면에 선택한 지표

| 형태 | 지표 | 선택 이유 |
| --- | --- | --- |
| 핵심 차트 1 | 일별 Top 10 관측 매출 합계 추이 | 날짜별 흥행 규모의 변화를 결측 구간과 함께 볼 수 있다. |
| 핵심 차트 2 | 영화별 일별 Top 10 관측 매출 합계 Top 5/10 | 관측 기간에 어떤 영화가 매출을 이끌었는지 비교할 수 있다. |
| 보조 수치 1 | 일별 Top 10 관측 관객 합계 | 매출 변화와 함께 관측 관객 규모를 확인할 수 있다. |
| 보조 수치 2 | 관객당 관측 매출 | 관객 한 명당 관측 매출의 대략적인 크기를 파악할 수 있다. |

차트 제목과 안내에 **일별 Top 10 관측 데이터 기준**임을 명시한다. 전체 영화 시장 통계로 해석하지 않으며 순위 밖 영화의 매출을 0으로 추정하지 않는다.

## 두 날짜 수동 검산

데모 fixture의 일간 자료에서 2026-09-07과 2026-09-08을 골랐다. 세 영화의 관객당 매출은 각 10,000원이다.

| 날짜 | 관측 매출 직접 합산 | 관측 관객 직접 합산 | 화면 표시 |
| --- | --- | --- | --- |
| 2026-09-07 | 10,000,000 + 9,000,000 + 6,000,000 = **25,000,000원** | 1,000 + 900 + 600 = **2,500명** | **0.25억 원** |
| 2026-09-08 | 11,000,000 + 12,000,000 + 6,500,000 = **29,500,000원** | 1,100 + 1,200 + 650 = **2,950명** | **0.30억 원** (29,500,000원 반올림) |

두 날 합계는 54,500,000원과 5,450명이다. 표시 단위로 바꾸면 각각 **0.55억 원**, **5.5천 명**이며 관객당 매출은 54,500,000 ÷ 5,450 = **10,000원/명**이다. 영화 코드별 두 날 매출은 `DEMO001` 21,000,000원, `DEMO002` 21,000,000원, `DEMO003` 12,500,000원이다. 이 계산값을 단위 테스트와 브라우저의 날짜별 행에 대조한다.

## 구현 경로와 확인 방법

화면은 최대 4개의 날짜별 내부 API 요청을 동시에 보내며 완료 수와 날짜별 상태 개수를 갱신한다. 실패한 날짜의 버튼은 해당 날짜만 다시 요청한다. 기간·종료일을 바꾸면 이전 요청을 취소하고 늦은 결과도 무시한다. API는 기존 캐시 경로를 사용하므로 저장된 일간 자료가 유효하면 먼저 사용한다.

`DATA_MODE=demo`로 서버를 시작한 뒤 `/insights`에서 종료일 `2026-09-13`을 선택한다. 7일은 정상 7·빈 날짜 0, 14일은 정상 7·빈 날짜 7, 30일은 정상 7·빈 날짜 23이다. 14/30일에는 기간 합계·Top 순위·보조 수치를 숨기고, 정상인 7일의 점만 추이 차트에 남긴다. 종료일을 `2026-09-06`으로 바꾸면 전체 빈 기간 안내가 나온다.

기존 구현 계획의 단일 `/api/insights` 집계 API 대신, 이번 화면은 날짜별 진행률과 그날만 재시도 요구에 맞춰 `/api/boxoffice`를 날짜별로 호출한다. `/api/insights` 계약은 향후 서버 집계가 필요할 때 다시 검토할 계획 항목이며 현재 구현된 API로 안내하지 않는다.
