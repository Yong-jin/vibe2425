# 영화 박스오피스 인사이트 대시보드 구현 계획

상태: 구현 전 계획 / 기준: [PRD](../PRD.md), [아키텍처](../ARCHITECTURE.md), [작업 지침](../AGENTS.md), [데이터 모델](../ERD.md), [단계별 계획](../PLAN.md)

## 1. 현재 위치와 결정 기준

Next.js(App Router)·TypeScript 실행 뼈대와 Vitest·Playwright가 있고, F1 목록 화면은 `DATA_MODE=demo`에서 2026-09-07~13 가상 데이터로 동작한다. `DATA_MODE=live`는 KOBIS 직접 호출·검증·응답까지 구현했다. F2는 준비 화면이며 Supabase 저장·공유 캐시는 없다. 이 문서는 **다음 구현의 목표 계약**을 정의한다. F1의 `data / meta` 형식은 두 모드에 적용되었다.

- 제품 동작과 완료 판정은 PRD의 AC를 우선한다. 캐시·오류 흐름은 ARCHITECTURE.md를 따른다.
- 저장 방식은 PLAN.md에서 채택한 **영화·조회 기간·기간별 실적 세 테이블**을 단일 데이터 기준으로 삼는다. 구현 전에 ARCHITECTURE.md의 `boxoffice_cache.payload` 설계와 AGENTS.md의 ‘정규화 대안’ 표현을 갱신한다. 독립적인 JSONB 원본 캐시를 함께 만들지 않는다.
- 로컬 비밀값은 `.env.local`의 `KOBIS_API_KEY`, `SUPABASE_SECRET_KEY`에만 둔다. `SUPABASE_URL`과 `DATA_MODE`도 같은 파일에서 로컬 설정할 수 있다. 비밀값을 브라우저·Git·로그·응답에 넣지 않는다. 배포 환경의 비밀값 주입 규칙은 배포 전 AGENTS.md에 별도로 확정한다.
- demo는 가상 데이터와 시나리오 선택을 유지한다. live는 실제 API·DB만 사용하며 demo 데이터를 실패 시 대체 자료로 내놓지 않는다. live의 초기 조회는 한국 시간 기준 **전일·일간**으로 바꾼다. demo의 2026-09-13 초기값은 샘플 시연 전용이다.

## 2. 화면 상태와 사용자 안내

| 상태 | 판정 | F1 목록 화면 | F2 인사이트 화면 |
| --- | --- | --- | --- |
| 로딩 | 현재 선택 조건의 요청 진행 중 | 로딩 안내·표시. 새 조건으로 바꿀 때 이전 요청 취소 또는 결과 무시 | 기간·Top 선택 시 로딩 안내. 이전 결과를 보이면 이전 조건임을 명시 |
| 성공 | 완전한 유효 데이터 | 순위·영화명·개봉일·매출·관객수·누적 관객수 표, 실제 집계 기간·조회 시각 표시 | 날짜별 매출·관객 추이, Top 5/10, 기간 합계·일평균 매출 표시 |
| 정상 빈 결과 | 성공한 원본 조회에 항목이 없음 | ‘선택한 기간의 박스오피스 데이터가 없습니다.’와 조건 변경 안내 | 분석 날짜가 모두 성공적으로 비었으면 지표 `—`와 기간 데이터 없음 안내 |

| 부분 집계 | 인사이트 일부 날짜가 비거나 실패, 또는 지표에 유효하지 않은 숫자 존재 | 필드 오류가 있으면 해당 셀 `정보 없음`과 품질 경고 | 포함·제외 날짜 수와 제외 사유, 결측 차트, `부분 집계` 표시. 실패 날짜에는 재시도 제공 |
| 오래된 캐시 | 외부 갱신 실패, 허용된 이전 정상 데이터 존재 | 이전 결과·마지막 성공 시각·갱신 실패·재시도 안내 | 해당 날짜를 stale로 표시하고 부분 집계 경고. 최신 자료처럼 표시하지 않음 |
| 오류 | 요청·DB·외부 API 실패로 제공 가능한 자료 없음 | 오류 안내와 재시도. 이전 표를 유지하면 이전 조건·갱신 실패를 표시 | 모든 날짜 실패 시 전체 오류. 일부 실패라면 부분 집계로 처리 |
| 입력 오류 | 날짜·기간·선택값이 허용되지 않음 | 해당 필드 안내, 조회 실행 차단 | 해당 필드 안내, 분석 실행 차단 |

검색은 이미 받은 F1 결과 안에서만 수행한다. 검색어의 앞뒤 공백을 제거하고 부분 일치로 필터링하며, 비우면 전체 목록을 복원한다. 날짜·유형 변경 후 늦게 도착한 응답이 현재 결과를 덮어쓰지 못하도록 요청 식별자와 취소 신호를 사용한다.

## 3. 화면·서버·DB 책임

| 계층 | 책임 | 하지 않는 일 |
| --- | --- | --- |
| 화면 (`/`, `/insights`) | 입력·접근성·표·차트·상태 안내, 현재 목록 검색, 재시도, 최신 요청만 반영. 숫자 문자열은 정밀도를 보존해 원/명 단위로 표시 | KOBIS 직접 요청, 비밀키 보유, DB 직접 접근, 누적 수치의 날짜별 합산 |
| 내부 API Route Handler | 서버 입력 검증·호출 제한·HTTP 상태와 응답 계약, `DATA_MODE` 분기, 비밀값 없는 관측 기록 | 브라우저에 내부 오류 상세·키 전달, demo 실패를 live 데이터로 위장 |
| 서버 서비스·KOBIS 어댑터 | KOBIS 요청, 응답 구조·숫자 문자열 검증, 집계 기간 대조, 캐시 조회·갱신·저장본 대조, BigInt 집계·결측 분류 | 잘못된 수치를 0으로 대체, API 오류를 정상 빈 결과로 캐시 |
| Supabase Postgres | 세 테이블의 공유 결과·조회 시각·만료 시각·상태 저장, 제약·RLS·원자적 갱신 RPC, 별도 갱신 임대·호출 제한 메타데이터 | 공개 클라이언트가 실적 또는 운영 메타데이터를 읽거나 쓰도록 허용 |

`movies(movie_cd PK, movie_nm, open_dt)`, `boxoffice_periods(period_id PK, UNIQUE(schema_version, period_type, query_date, options_key), result_status, fetched_at, expires_at, 실제 기간)`, `boxoffice_results(PK(period_id, movie_cd), 양쪽 FK, rank, sales_amt, audi_cnt, sales_acc, audi_acc, quality_warnings)`를 ERD.md 기준으로 구현한다. 금액·관객수 DB 컬럼은 정확한 정수형 `numeric(30,0)`을 사용하고 API JSON에서는 정수 문자열 또는 `null`로 보낸다. 정상 빈 결과는 기간 행 `empty`와 실적 0행으로 저장한다. 원본 오류·타임아웃은 성공 데이터로 저장하지 않는다.

## 4. 내부 API 계약

요청 한 줄: **`GET /api/boxoffice?date=YYYY-MM-DD&type=daily|weekly|weekend` → 해당 집계 기간 목록**, **`GET /api/insights?endDate=YYYY-MM-DD&days=7|14|30&top=5|10` → 종료일 포함 일간 추이·Top·지표**.

| API | 요청 파라미터와 검증 | HTTP 200의 `data` | HTTP 200의 `meta` |
| --- | --- | --- | --- |
| `/api/boxoffice` | `date` 필수. 실제 달력 날짜·한국 시간 기준 미래 제외. `type`은 세 값 중 하나, 생략 시 `daily`. 검색어는 받지 않음 | `{ items: [{ movieCd, movieNm, rank, openDt, salesAmt, audiCnt, salesAcc, audiAcc }] }`. `rank`는 검증된 정수 또는 `null`, `openDt`는 날짜 또는 `null`, 금액·관객수는 정수 문자열 또는 `null` | `{ status, mode, source, queryDate, periodType, periodStart, periodEnd, fetchedAt, expiresAt, warnings }` |
| `/api/insights` | `endDate` 필수, 유효한 한국 날짜·미래 제외. `days`는 7/14/30, 생략 시 7. `top`은 5/10, 생략 시 5 | `{ series: [{ date, salesAmt, audiCnt, status }], topMovies: [{ movieCd, movieNm, salesAmt, audiCnt }], summary: { salesAmt, audiCnt, averageDailySalesAmt } }`. 금액·관객수는 정수 문자열 또는 `null`; 결측 날짜의 값은 `null` | `{ status, mode, startDate, endDate, includedDates, excludedDates: [{ date, reason }], fetchedAt, warnings }` |

공통 성공 외형은 `{ "data": { ... }, "meta": { ... } }`다. `meta.status`는 `ok | empty | partial`이며, F1의 stale 대체는 `partial`과 `source: "stale"`로 표시한다. `source`는 F1에서 `cache | kobis | stale | fixture`; `mode`는 `demo | live`다. demo F1의 `fetchedAt`은 실제 KOBIS 수집 시각이 아닌 고정된 가상 fixture 시각이며, `expiresAt`은 `null`이다. 조회 시각·만료 시각이 없는 다른 demo 응답에서는 해당 필드를 `null`로 둔다. F2는 날짜별 출처·오류 사유를 `excludedDates`와 `warnings`에 담는다. 집계는 **API 목록 내 영화의 합계**이며 전체 시장 합계라고 표현하지 않는다.

실패 외형은 `{ "error": { "code": "...", "message": "사용자에게 안전한 안내" }, "meta": { "status": "error", "mode": "demo|live" } }`로 통일한다. 서버 내부 원인·요청 URL·키는 포함하지 않는다.

| HTTP | 조건 | 화면 대응 |
| --- | --- | --- |
| 200 | 유효한 데이터 `ok`, 정상 빈 응답 `empty`, 일부 날짜/허용 stale 사용 `partial` | 상태별 결과·안내 표시. 정상 빈 응답을 HTTP 오류로 취급하지 않음 |
| 400 | 잘못된 날짜·유형·기간·Top 등 요청값 | 입력 안내, 자동 재시도 없음 |
| 429 | 내부 요청 제한 초과 | 잠시 후 다시 시도 안내, 서버가 `Retry-After` 반환 |
| 502 | KOBIS 오류 응답·인증 실패·구조 오류 또는 네트워크 실패, 대체 캐시 없음 | 조회 오류와 재시도. 인증 상세·키 비노출 |
| 504 | KOBIS 요청 또는 전체 요청 시간 초과, 대체 캐시 없음 | 시간 초과 안내와 재시도 |
| 503 | 서버 설정 누락, DB 장애로 조회 불가하며 외부 직접 조회도 불가, 갱신 임대 대기 상한 초과 | 일시 이용 불가 안내·재시도 |

F2는 일부 날짜만 실패해도 나머지 날짜를 계산할 수 있으면 200/partial이다. **모든 날짜가 정상 빈 응답**일 때만 200/empty이고, **모든 날짜가 실패**하면 적절한 502/503/504를 반환한다. 빈 날과 실패 날만 섞였으면 200/partial이며 `summary` 값은 `null`이다. 응답에 BigInt를 직접 넣지 않는다.

## 5. 요청 처리 순서·유효 기간·실패 처리

**입력 검증 → 캐시 조회 → 외부 호출 → 원자적 저장 → 저장본 재조회·대조 → 응답.** 유효 캐시가 있으면 외부 호출 이하를 건너뛴다. demo는 검증 후 fixture를 반환하고 DB·KOBIS 경로에 들어가지 않는다.

| 단계 | 처리 및 제한 | 실패 시 행동 |
| --- | --- | --- |
| 1. 입력 검증·제한 | KST 날짜, 허용 값, 미래 날짜, 내부 요청 제한을 서버에서 확인. 기본 요청 제한은 동일 클라이언트 30회/분. 실제 외부 호출 상한은 KOBIS 공식 한도 확인 후 그 이하로 설정 | 잘못된 입력 400, 요청 초과 429. 외부 호출·DB 쓰기 없음 |
| 2. 캐시 조회 | 버전+기준일+유형+고정 외부 옵션 키 조회. DB 조회 제한 2초. `expires_at > now`면 즉시 반환. 인사이트는 최대 30개의 **일간** 결과만 조회 | 누락·만료면 3단계. DB 장애면 제한된 KOBIS 직접 조회로 진행하되 장애 기록. 정상 empty와 캐시 미스를 구분 |
| 3. 외부 호출 | 같은 키의 만료 가능한 DB 갱신 임대를 원자적으로 획득하고 KOBIS 요청. 외부 단일 호출 제한 4초. 일간과 주간/주말 매핑·응답 기간·구조·필드 검증. 인사이트는 동시 호출 최대 4개, 전체 시간 예산 15초 | 임대 대기 상한 2초를 넘으면 허용 stale 또는 503. 오류 구조·네트워크 실패는 502, 타임아웃은 504. 허용 stale가 있으면 200/partial로 제공하고 마지막 성공 시각·갱신 실패 표시. 무제한 재시도 금지 |
| 4. 저장 | 정상 데이터 TTL **6시간**, 정상 빈 응답 TTL **10분**. 영화 upsert, 기간 upsert, 기존 실적 교체를 하나의 RPC 트랜잭션으로 실행. DB 저장 제한 2초. 실패·오류를 empty로 저장하거나 기존 만료 시각을 연장하지 않음 | 저장 실패·타임아웃이면 검증된 KOBIS 결과를 `source: kobis`와 저장 경고를 붙여 반환. 이전 DB 정상 상태 보존·비밀값 없는 운영 기록 |
| 5. 저장본 대조 | 저장 성공 시 같은 기간을 DB에서 다시 읽어 상태·실제 기간·movieCd 집합·순위·금액·관객·누적값과 만료 시각을 검증된 원본과 대조. 재조회 제한 2초. 문자열 숫자는 정규화된 정수값으로 비교 | 불일치·재조회 실패면 DB 결과를 제공하지 않고 방금 검증된 KOBIS 결과와 저장 검증 경고를 반환. 갱신 실패로 기록해 원인 조사·재시도 대상으로 삼음 |

F1 서버 요청의 전체 시간 예산은 **12초**다. 단계별 제한보다 전체 예산을 우선하며 초과 시 허용 stale가 없으면 504다. F2는 **15초** 내 결과가 준비된 날짜만 집계하고, 미완료 날짜를 오류로 기록해 부분 집계로 반환한다. 평균 분모에는 해당 지표의 완전한 유효 데이터가 있는 날짜만 넣는다. 일부 숫자 필드가 잘못되면 `null`·품질 경고로 처리하고 0으로 대체하지 않는다.

stale 대체는 **만료 후 24시간 이내의 마지막 정상·비어 있지 않은 결과**에만 허용한다. 정상 빈 결과나 그보다 오래된 값은 stale 자료로 제공하지 않는다. 캐시 갱신 정책과 호출·시간 제한은 초기 설계값이며 실제 KOBIS 한도, Vercel 실행 제한, Supabase Free 조건을 확인한 기록을 남기고 배포 전 확정한다. 서버 비밀키를 쓰는 테이블·RPC는 공개 클라이언트 접근을 차단한다.

## 6. 우선순위와 단계별 완료 확인

필수 흐름을 먼저 구현하고, 각 단계는 검증·결과 보고 후 [PLAN.md](../PLAN.md)의 다음 Phase 승인 규칙을 따른다. 이미 만든 demo는 프로토타입으로 유지하되 이 표의 live 완료로 계산하지 않는다.

| 순서 | 우선순위·작업 | 해당 PLAN Phase | 끝났다는 확인 기준 |
| --- | --- | --- | --- |
| 1 | **필수 — 계약·문서 정합성.** 이 문서의 응답 형식 확정, ARCHITECTURE.md와 AGENTS.md를 세 테이블·실제 명령어에 맞춤 | 1 보완 | 저장 모델·명령·demo/live 구분에 문서 충돌이 없고 관련 fixture 계약 검사가 통과 |
| 2 | **필수 — KOBIS 어댑터.** live 일간·주간·주말 호출, 날짜·응답 기간·숫자 검증, 실패 분류 | 2 | PRD AC 1·2·4 서버 검사 통과, 실제 세 유형 응답과 기간 확인. 키가 없으면 실연동 미실행으로 남김 |
| 3 | **필수 — 정규화 DB와 캐시.** 마이그레이션·RLS·RPC, TTL·임대·저장본 대조·오류 복구·호출 제한 | 3 | 격리 DB에서 중복 저장·원자성·정상 empty·만료·stale·DB 장애·저장본 불일치 검사가 통과하고 공개 접근 차단 확인 |
| 4 | **필수 — F1 live 전환.** demo UI 재사용, 전일 기본값, 실제 데이터·캐시 메타 표시, 오류 복구 | 4 | PRD AC 1~5·9~11·13을 live 내부 API와 화면에서 확인. 빠른 조건 변경에도 최신 결과 유지 |
| 5 | **필수 — F2 인사이트.** 일간 결과 공유, 7/14/30일 추이·Top 5/10·보조 지표·부분 집계 | 5 | PRD AC 6~8·12와 수동 계산 fixture 일치. 누적값 비합산·결측 및 전체 empty/error 구분 확인 |
| 6 | **출시 필수 — 보안·운영·배포.** 전체 AC, 키 비노출, 무료 조건, 배포 설정·관측·롤백 | 6 | AC 1~15 통과, 최신 공식 조건·확인일 기록. 배포 승인 후 실제 URL의 목록·인사이트·복구 동작 확인 |

파싱·DB 저장·지표 계산을 바꾸는 단계에는 [box-office-verification Skill](../.agents/skills/box-office-verification/SKILL.md)을 적용해 통과·실패·미실행을 구분한다. 단위 fixture, 격리 DB, 실제 KOBIS, 브라우저 검증을 각각 기록한다.
